# DFM11 MixedLM experiments

The user authorized B and Transformer MixedLM, both target-only, after the
[existing objective ablations](2026-11-14-dfm11-objective-ablation.md).
This means Schneider-Kamp Lab llama.cpp fork semantics, not the previously
misnamed mixed-objective batch-training proposal. The separate append-only
variant (only new prompt queries, retain the previous answer's causal KV) is
recorded as future work and is not scheduled.

## Attention contract

`models/mixedlm.py` reconstructs blocks ending at complete Gemma4 assistant
headers (`<|turn>model\n`). The initial prompt attends bidirectionally. Each
subsequent prompt block includes the preceding assistant answer and new input;
it attends bidirectionally within the block and to earlier frozen prefix keys.
Earlier queries cannot see newer blocks. The current target answer is causal.
Target-only labels, sampled data order and packing remain unchanged. Frozen
forward history does not itself impose gradient detachment; B retains its
separate established BP warmup.

Flattened samples do not retain arbitrary native API extension boundaries.
Tool-bearing prompts explicitly use a full-prefix refresh, which the fork API
permits, because the exact tool-continuation boundaries are not recoverable.
Prompts without assistant headers are one full-prefix block. Template header
matching assumes the canonical tokenizer protocol; literal injected special
headers are not distinguished from structural headers. These are declared
training/serving policies, not claims of reconstructing every original API call.

The source semantics are pinned to local llama.cpp
`a800a5ff30fc9c37e0fa57629d0acf58a7340bea`; see the
[integration runbook](../model-architecture/prefixlm-upstream-integration.md).

## Implementations and limitations

Training uses two FA4 varlen calls for prompt blocks and answer suffixes, with
packed-example isolation and accumulated gradients for repeated historical K/V.
The data loader builds routes once per batch. MixedLM is opt-in through
`+arch.attn_type=mixedlm` and requires `data.target_only=true`.

HF exports declare `MixedLMForCausalLM`, the exact header/tool token IDs and
`assistant-header-blocks-v1-tool-full-refresh`. The vLLM adapter replays the block
mask on cold prompts and retains ordinary per-cycle KV for answer decoding.
It requires eager execution, disabled prefix caching and disabled chunked
prefill. Standard prefill executes to populate KV, then corrected block outputs
replace its outputs. This incurs extra prefill work; it is not an optimized
cross-request cache-reuse implementation. Generic HF inference requires an
explicit block mask; native cached inference intentionally rejects MixedLM.

Full-size throughput and peak memory have not yet been measured. Repeated
history gathers can cost more memory for many-turn prompts. Small compiled
training and vLLM tests cannot establish full-size performance.

# Decision preparation

Owner initially authorized conversion/tokenization on October 26, explicitly **no sampling**.
Later the same day this was superseded by authorization to sample with higher
repeats for selected small sources. The separate DFM16 sampler completed;
see [sampling policy and receipts](dfm16-plan.md). The preparation commands
below themselves still never sample.
Inputs are the pinned snapshots listed in `config/dfm16_decision_sources.json`.
Historical DFM data and running training/evaluation jobs are not modified.

## Commands and artifacts

Run from HRM-Text using the hrm environment:

```bash
python -m scripts.prepare_dfm16_decision_curriculum
python -m scripts.tokenize_dfm16_decision_curriculum
python -m scripts.prepare_dfm16_decisions --workers 64
python -m scripts.report_dfm16_decision_preparation
```

Main output: `data/dfm16/decisions-v1/<source>/` with `input/{direct,thinking}`,
`tokenized/{direct,thinking}`, `conversion.json`, `examples.json`,
`rejected.jsonl` and `prepared.json`. Aggregate `preparation_summary.json`
is generated by the reporting command. The live log is
`data/dfm16/decisions-preparation.log`. Curriculum has its own directory
`data/dfm16/decision_curriculum`; Hetionet remains separately prepared.
No command above invokes an epoch sampler.

Conversion is streamed from Parquet/JSONL/JSON arrays, producing 64 shards
per mode. HF chat tokenization uses 64 processes with internal tokenizer
parallelism disabled, the Gemma 4 tokenizer and DFM15 native template.
Reasoning examples explicitly enable thinking; direct labels do not.
Length diagnostics count examples over 4096/8192 tokens; no text, reasoning
or decisive context is truncated to force a fit. Later sampling must use
appropriate complete-example length eligibility.

## Contracts

- MCQA preserves source Answer/boxed contracts. OpenScience well-formed think
  spans become native reasoning fields; malformed spans and mismatched
  single-letter final answers are rejected with source coordinates.
- Unordered choices are deterministically shuffled with target alignment;
  ordinal order is retained. LocalLLaMA/Open-Jev soft labels become requested
  probability distributions, not falsely certain argmax answers.
- AgentGym actions use a declared `environment_step(command)` native tool
  wrapper for the simulator's original command language. This is deliberately
  not a claim of per-API BFCL-style schema supervision. Observations become
  linked tool responses; original thoughts become native reasoning. Legacy
  response-format tails are removed. Initial untrained acknowledgements are
  omitted; each selected action target retains its preceding trajectory.
- Mind2Web uses native browser_action operation/node/value arguments, past
  actions only, shuffled-label-independent DOM candidate order, no positive
  annotation flags. Ambiguous multi-target actions are not forced to one
  arbitrary label. Source normalized CLICK/TYPE/SELECT operations are used.
- NLI4CT and FEVER supply actual evidence, not just labels. QuALITY uses
  one-based answer indices. PubMedQA uses abstracts and native yes/no/maybe
  labels; unlabeled rows are excluded.
- CommitPackFT retains full before/after code and edit requests; 5% hash
  buckets of repository groups are reserved because the source is unsplit.
  Empty/unchanged code cases are logged, not replaced by invented content.
- Provenance includes pinned repo/revision/file hash, row coordinate,
  available group ID and license. Source-level terms remain as reported;
  conversion does not assert unresolved licensing has been resolved.

## Deduplication and recovery

Exact message/tool/target duplicates are removed within these additions.
Science/MCQA use a normalized question key with only recognized instruction
prefixes removed; OpenScience takes precedence to retain reasoning. This is
not fuzzy deduplication and not a full inherited-corpus overlap check.

One flock protects a preparation root. SQLite dedup state is transactional
per source; a complete conversion is published via staging-directory rename.
Sources with no complete receipt have stale keys removed on restart. Existing
receipts require the same converter/registry fingerprint; use a new output
directory for changed converters instead of silently mixing versions.
Tokenization completion is checked against converted target counts and
array lengths. Incomplete sources are never described as ready.

## Verification and current status

Initial full-file first-row schema probes covered every selected source file;
one converted example/trajectory per source passed real Gemma prefix/target
tokenization. Focused adapter and existing chat-tokenizer tests: **16 passed**.
These checks establish format behavior, not semantic quality for every row.

Curriculum complete: **90,120 examples, 67,034,223 tokens**, zero tokenizer
skips; 4,185 examples exceed 4096 and 2,097 exceed 8192 tokens.

Completion update (2026-10-26), superseding the earlier in-progress status:
all 13 sources and the curriculum have completed conversion/tokenization:
**3,356,100 examples, 11,325,266,140 tokens**. No epoch sampling was run.
These are prepared-source totals, not sampled per-epoch contributions;
Hetionet is separate. See `preparation_summary.json` for per-source counts.
OpenScience contributes 9,755,179,239 tokens, with 810,402 examples above
4096 tokens. Mind2Web has 7,124 of 7,147 examples above 4096 tokens.
These sources require explicit length eligibility decisions before sampling.
Mind2Web action-level omissions for ambiguous/unsupported actions are not
individually recorded in the row-level rejection log; retain the pinned
source snapshot for a more detailed omission audit if needed.
The OpenScience pinned Parquet contains **1,600,812** rows; use this measured
count instead of inconsistent Hub viewer estimates.

DFM Mimir **0.1.5 (build 10)** is a local chat app with the official **Mimir v1.5 Q4_K_M (4-bit)** model included. No account, model download or model import is required to start chatting. Desktop packages also include an optional OpenAI-compatible local API and a standalone headless server.

- **macOS:** mount the DMG, drag **DFM Mimir.app** into Applications, then open it there and eject the image.
- **Linux/Windows:** extract the entire archive and run `dfm-mimir` / `dfm-mimir.exe`. Keep the libraries, assets and server executable together.
- **Android:** install the APK. Open **Settings → Model**, choose limits/backend, then press **Load model**. Startup deliberately leaves the model unloaded so settings remain accessible. Start with CPU, 1,024 context tokens and 512 reply tokens. After a freeze, force-stop the app and reopen it to change settings. Changing an initialized backend also requires force-stop/reopen.

Each package is roughly 1.1–1.2 GB because it includes the model. Download size is not RAM use: model loading and longer contexts require additional memory. Android also extracts a model copy into app-private storage, so allow space for both the APK and extracted model, plus a temporary copy during updates. Each download has a matching `.sha256` sidecar in Assets.

These packages retain development signing: macOS is ad-hoc signed and not notarized; Android uses the development key; Windows is unsigned. If macOS blocks the app, use the per-app **Open Anyway** option in System Settings → Privacy & Security only if you trust the download. Physical Android Vulkan remains unqualified. Linux/Windows packages do not include CUDA or Vulkan acceleration. No distributable iOS package is included. iOS distribution uses TestFlight separately. See the [TestFlight handoff](https://github.com/schneiderkamplab/HRM-Text/blob/dfm-mimir-v0.1.5/native/app/TESTFLIGHT.md).

## Settings and appearance

**Appearance → Text size** offers 75–200% scaling with a 100% reset, in addition to system accessibility settings. **Advanced** contains compaction, profiles, MixedLM and the desktop API. **Online** contains optional search and feedback. Tab changes preserve unfinished edits.

## Chat, context and model selection

The app provides saved conversations, streaming replies, stop, sharing, model/backend settings and a context-use indicator. **Settings → Model** controls context length and reply budget. Desktop automatic sizing uses available memory; Android starts with conservative manual limits. The bundled model was trained at **4,096 tokens**; configurable contexts up to **32,768** are experimental and may reduce answer quality or exceed available memory.

**Automatically compact context** summarizes older turns when context fills, aiming to free at least half the context when the current prompt and reply reservation permit. Oversized prompts or historical turns are split into bounded pieces for summarization. Original messages remain in the transcript; shortened text is kept separately for inference. **Show compaction summary in chat** reveals summaries where they occurred, including while they stream. Compaction is lossy and can take multiple model passes. Disabling it restores original text for inference, which may exceed context.

**MixedLM mode** is an optional approximation that reuses representations of older turns to reduce repeated prompt processing. It is on by default for new settings; a saved choice is preserved. It can change answers. Turn it off for exact PrefixLM.

**Temperature** (0–2, default 0) and **Repetition penalty** (1–2, default 1.1) are adjustable in settings and saved. Higher temperature adds variety; 0 uses greedy decoding. The repetition penalty discourages the last 64 generated tokens within each reply; 1 disables it. The former saved 1.0 default upgrades once to 1.1, while other customized values remain. These controls do not override API request sampling or compaction's deterministic defaults.

Assistant replies and visible summaries render basic Markdown, including headings, emphasis, lists, quotes and code blocks, even while streaming. User messages remain literal; stored/shared text is unchanged. Images render as text placeholders. Links open an inspect/copy dialog, without network access.

In **Settings → Model → Choose or download a model…**, view the selected model, download sizes/status and installed models; select another model or import a local GGUF. Enable **Allow model downloads and discovery**, then **Check for newer models**, to refresh the catalog. Networking is optional and off by default; it is not needed for bundled chat.

The curated catalog and automatic discovery cover official `danish-foundation-models` repositories whose names contain both `mimir` and `gguf`, case-insensitively. Official corrected Q4_K_M, Q8_0 and BF16 exports are listed. Under **Additional Hugging Face repositories → +**, add an exact public `owner/repository` ID, such as `noctrex/DFM-Mimir`, to include third-party GGUFs. Adding an ID does not enable networking. Removing it stops its listings/download access and preserves already installed files.

Downloads are pinned to repository revisions and checked against size/SHA-256 metadata. Discovered models are unverified and use conservative fallback settings; arbitrary architectures are not guaranteed to work. Split GGUFs and private/gated authentication are not supported. Model refresh/download contacts GitHub and Hugging Face; it does not send chats.

## OpenAI-compatible API on desktop

**macOS, Linux and Windows** expose an optional **text Chat Completions subset** of the OpenAI API. Android does not expose this API.

1. Load a model, open **Settings → Advanced**, choose the port (default `8080`) and enable **OpenAI-compatible local API**.
2. The active address appears in settings. Configure your client with base URL **`http://127.0.0.1:8080/v1`** and model **`dfm-mimir`**.
3. The API starts off by default; enable it again after restarting the app. Turning it off cancels API requests. Closing the app stops it.

The port is configurable while the API is stopped. The bind address is fixed to **127.0.0.1**, so this version accepts local callers only; LAN listening and browser-origin/CORS requests are not supported. Set environment variable `MIMIR_API_KEY` before launching the app/server to require `Authorization: Bearer YOUR_KEY`. Otherwise no API key is required; clients that insist on one can use a placeholder. No OpenAI account is needed.

Supported endpoints are `GET /v1/models` and `POST /v1/chat/completions`. For example, after starting the API:

```sh
curl http://127.0.0.1:8080/v1/models
curl http://127.0.0.1:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"dfm-mimir","messages":[{"role":"user","content":"Hej Mimir!"}],"max_tokens":64}'
```

The example uses POSIX shell quoting. Responses can be ordinary JSON or SSE with `"stream":true`. Supported sampling controls include `temperature`, `top_p`, `seed`, and one token budget (`max_tokens` or `max_completion_tokens`). Messages must contain text: an optional initial `system` message, then alternating `user`/`assistant` turns ending in `user`. Mimir's own chat template is applied.

API requests share the UI's loaded model, execute serially, and do not create or modify saved chats. Clients must supply conversation history. API requests do **not** use automatic compaction or cross-request MixedLM reuse; oversized requests return an error. Tools/function calling, images/audio, developer-role messages, structured response formats and the Responses API are unsupported. This is not full OpenAI API parity. See the [API guide](https://github.com/schneiderkamplab/HRM-Text/blob/dfm-mimir-v0.1.5/native/app/API.md) for the complete field/error/queue limits.

## Headless desktop server

No GUI or display server is required. The included server loads the packaged model and exposes the same API:

```sh
# Linux: run from the extracted package
./dfm-mimir-server --port 8080

# macOS: run from Terminal after installing the app
"/Applications/DFM Mimir.app/Contents/MacOS/dfm-mimir-server" --port 8080
```

```powershell
# Windows PowerShell: run from the extracted package
.\dfm-mimir-server.exe --port 8080
```

Use `--help` for options, including `--model FILE.gguf`, `--profile FILE.json`, `--device auto|cpu|DEVICE`, `--context TOKENS`, `--max-tokens TOKENS`, and `--port PORT`. Default context sizing is automatic and the default reply budget is 512 tokens. An imported model uses the bundled profile unless you supply another profile. Stop with **Ctrl-C**. A separately launched GUI and server each load their own model and consume additional memory. The same loopback-only binding and optional `MIMIR_API_KEY` authentication apply.

## Optional chat feedback and privacy

Thumbs up/down can share the selected conversation with the Mimir team to improve future Mimir and other DFM models. **Online feedback is off by default**, independently of model-download permission. The first thumb click asks whether to enable it; declining leaves local chat usable. Change this under **Settings → Online → Allow online feedback**.

Every submission requires **Confirm and send** after a preview showing the exact chat, any compaction summary (including hidden summaries), optional comment, editable device-generated pseudonym and limited app/model/settings metadata. The separate **CC BY 4.0 publication permission defaults on** and can be unchecked. Enabling feedback alone sends nothing; cancelling sends nothing. Network denial or submission failure affects only feedback, not local chat.

Submissions go to the team's Cloudflare service. D1 database storage/execution uses EU jurisdiction; Worker request processing may occur elsewhere. Publication is a separate team review decision, not automatic on submission. The app contains no Cloudflare administrative credentials or feedback read/export access. Contact: **petersk@imada.sdu.dk**. OS networking permissions are declared; the consent switches are app-level controls, not a general OS Internet-permission prompt.

## Optional web search

In **Settings → Online**, enable **Allow online search**, enter your issued
`mimir_<hex>` key and choose **Save search key**. Keys are masked with a visibility
toggle; secure storage is optional. The model can then call the search tool with
a query and use its results in the reply. Stop cancels an active search. Turning
search off hides key controls and removes the tool definition without deleting
the saved key. There is no separate search button.

Queries go through the Mimir Cloudflare service to Jina AI and may include chat
details. The provider key remains on the server. Search is off by default and
failure does not prevent offline chat. Tool results consume context and may be
inaccurate. Search is available in the chat UI, not the desktop API. Linux needs
a Secret Service to remember keys; session-only use remains available otherwise.

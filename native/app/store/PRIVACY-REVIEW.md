# Privacy preparation — not a published policy

Prepared from the client and Worker code on 2026-10-01. This is an implementation
inventory for SDU approval, not legal advice or a completed App Store declaration.

Concise public-facing draft: [PRIVACY.md](PRIVACY.md). Proposed submission
answers: [SUBMISSION-DRAFT.md](SUBMISSION-DRAFT.md). Both remain drafts.

## Data flows

| Feature | Data leaving the device | Destination / purpose | Persistence |
| --- | --- | --- | --- |
| Ordinary chat and compaction | None from inference | On-device model | Chats/settings/model files stored locally; OS backups may include app data |
| Catalog and model discovery/downloads | HTTP request metadata, repository/file requested | GitHub catalog and Hugging Face / their delivery providers | Provider policies; downloaded weights stored locally |
| Optional search | Query generated by the model, Mimir access key to Worker; network metadata | Cloudflare Worker forwards query with server-held Jina credential to Jina AI | Worker D1 stores key hash, Jina mapping and daily usage count; application code does not persist queries/results in D1; provider processing/logging requires policy review |
| Confirmed feedback | Current chat including compaction summary, rating, optional comment, attribution pseudonym, consent choices, receipt ID, app/platform/model/context/reply/MixedLM information | Cloudflare Worker + D1; Mimir team research and model improvement | No automatic expiry currently; manual deletion available; provider backup retention separate |
| Optional local API (Mac) | Requests/responses between app and configured clients | Local listener; binding beyond loopback may expose chats to other machines | Normal app conversation/state behavior; no cloud API relay |

The feedback pseudonym is randomly generated and stored on the installation; it
is not a hardware-derived identifier. It can still link multiple submissions.
Feedback can contain identifying information in free text. Do not describe all
submitted feedback as anonymous or unlinked.

Public-data permission defaults on in the confirmation dialog and can be switched
off. It grants CC BY 4.0 publication permission, distinct from permission to share
with the research team. Team review is required before export. Already published
copies and downstream reuse cannot be promised to disappear following deletion.

D1 was provisioned with EU jurisdiction. This does not establish that every
Cloudflare Worker, Jina request, provider log or backup is EU-only. Confirm the
actual processor agreements and transfer arrangements.

## Draft public-policy content to approve

Ordinary conversations are processed on your device. Online features are optional.
You may enable model downloads, web search or explicitly share chat feedback.
Search sends the model's search query through our Cloudflare service to Jina AI;
queries may include details from your conversation. The Jina service credential
stays on the server. Your Mimir access key is stored locally using platform secure
storage. Disabling search stops future search calls; it does not delete existing
provider records or revoke the key.

Before sharing feedback you can inspect the data and choose whether it may also
be published under CC BY 4.0 with the attribution name you provide. Feedback
includes the current chat and any compaction summary, even if that summary is
hidden in the chat display. Do not submit other people's private information.

Submitted feedback currently remains until manually deleted; there is no
automatic deletion schedule. Keep the receipt ID for a deletion request. Published
or previously distributed material may remain available under its license.

**Complete before publication:** legal data controller and contact; purposes and
legal bases; exact retention criteria and backup periods; processor/transfer
arrangements; rights and request process; institutional complaint/DPO details;
policy effective date; children/age policy. Align the service implementation with
any promised retention policy before collecting under it.

## Proposed App Store privacy labels for review

Do not select “Data Not Collected” just because core inference is local.

- Other User Content: submitted chats, summaries, comments, attribution text;
  purpose includes research/model improvement. Decide the correct Apple purpose
  (likely Other Purposes in addition to relevant App Functionality) explicitly.
- Identifiers: assess persistent feedback pseudonym and access-key/usage record as
  User ID, including whether data is linked to identity. Free text may identify a
  person even without an account. Do not assume “not linked” automatically.
- Search History: review Jina/Cloudflare retention and Apple's collection
  definition before declaring whether query handling counts as collected data.
- Other Data / Usage Data: map submitted model/settings/version metadata and
  per-key usage counters to Apple's current categories.
- No ad SDK or cross-app advertising tracking found in the reviewed client;
  do not claim tracking solely because an operational service sees network data.
- Optional-feedback disclosure exemption is not assumed: model-training/public
  dataset reuse must be assessed against all Apple's exemption conditions.

## Submission gates

1. Publish institution-approved support and privacy pages at stable HTTPS URLs.
2. Add an easily accessible privacy-policy link inside Settings (currently absent).
   Keep the offline explanation available without enabling online services; opening
   an external policy page should be an explicit user action.
3. Audit merged privacy manifests / required-reason APIs with Xcode's privacy report.
   Bundled dependency manifests alone are not proof of full compliance.
4. Reconcile final App Store labels with actual provider retention and approved
   policy. The app has no account creation, so no in-app account deletion flow is
   currently applicable; feedback deletion still needs a working process.
